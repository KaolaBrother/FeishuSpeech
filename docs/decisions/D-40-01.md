## Decision

### One route and independent asynchronous roots

Every accepted Fn interaction, regardless of the persisted `reviewBeforeInsert` or `autoInsert`
value, follows one route:

```text
capture/recording root  ──┐
                         ├─> streaming preview -> sealing -> editable -> confirming
recognition/provider root ┘             focus aid is telemetry only   └─ one delivery attempt
```

The capture/recording and recognition/provider/retry/replay lines remain separate asynchronous
roots. Fn release closes capture; the recorder callback barrier, queued/tail audio, recoverable
replay, and authoritative action 2 still settle in the existing generation. The review panel is a
third presentation axis. No root waits for panel rendering, editor focus, Send/Return confirmation,
delivery, or the other root; no review work adds journal backpressure or recognition dependency.

The retained recording overlay remains status-only. Its `正在聆听…` and `正在完成识别…` status is not
the transcript preview and is not an output channel.

### Destination capture and fallback authority

Before audio/provider work, capture the complete original frontmost application identity: positive
PID, bundle identifier, executable URL, and finite launch date. Running/frontmost identity must
agree before and after the typed AX capture.

- `exactCursor` remains preferred when Accessibility trust, Secure Input, role/subrole, focused PID,
  selected range, settable focus/range, and identity checks all pass. The original AX element and
  selection remain generation-bound.
- An ordinary non-secure strict-AX capability miss admits `applicationCurrentFocus` for the already
  captured application. It carries no AX element or selection and never recaptures an ambient target.
- Secure Input, secure/password roles, lost Accessibility trust, incomplete identity, PID reuse, or
  identity drift fail closed before the review starts.

The fallback proves the original application only, not the original control or caret. Confirmation never
activates that application, discovers a substitute, or retargets another PID; its opaque lease remains fixed.

### Durable panel and confirmation authority

`TranscriptionReviewState` is intentionally:

```text
idle -> streaming(preview) -> sealing(preview) -> editable(draft) -> confirming(draft)
```

Action 2 plus the recorder barrier freezes the exact authoritative draft, updates the coordinator
projection, and renders `.editable` with edit, Send, and qualified Return/Enter callbacks before
starting any presentation-focus await. There is no `editablePending` product state and no retry-
editing control. Activation, key-window, editor materialization, first-responder, timeout, or
cancellation results are typed presentation telemetry only; they cannot hide Send, disable Return,
revoke the draft, change revision/feedback, or invoke delivery.

The review panel retains its existing 520x320 initial size, 420x240 minimum, and 760x600 maximum.
Preview and native editor text use 18pt typography, and the read-only content remains below the
titlebar/traffic-light controls. The panel is the same instance through streaming, sealing, and edit.

Only two production sites can create `ReviewConfirmationIntent`: the actual Send button and the
qualified native Return/Enter handler. The intent is file-scoped and opaque; no zero-argument
coordinator confirmation or optional-revision bypass exists. D-39-01 remains unchanged:

- unmodified Return and keypad Enter confirm;
- Shift+Return and Shift+Enter insert one LF and do not confirm;
- Command+Return remains an explicit confirmation shortcut;
- marked-text Return goes to the input method; and
- Cancel, Escape, and window close discard without target output.

The v5 native arbiter additionally rejects blank/whitespace drafts, any modified or repeating Return,
wrong-window events, and events whose responder is not a descendant of the current key preview panel.
The panel is `.nonactivatingPanel`; if it cannot become key with the editor attached, visible Send remains
the bounded fallback and no global Return monitor or target Return suppression is installed.

The current review ID, generation, and exact callback revision must match. Whitespace-only and
over-cap drafts remain editable and make no delivery call. A per-character edit updates the
coordinator draft and clears stale feedback; it never calls an output service.

### Zero side effects before confirmation

From Fn press through recording, recognition, streaming preview, Fn release/sealing, action 2,
recorder-barrier freeze, focus assistance, every draft edit character, feedback, cancellation,
discard, failure, and cleanup, the review side-effect ledger must remain zero for:

- AX setters or target-control reads used as output;
- target keyboard/CGEvent posts or synthetic output signals;
- pasteboard reads, snapshots, writes, restores, and `changeCount` polling;
- copy/paste, delivery calls, retries, retargets, or target recapture.

Reading the captured identity, live trust, Secure Input, modifier, and epoch telemetry for a final
gate is observation, not output. Presentation focus may affect the FeishuSpeech panel only; it cannot
authorize target delivery.

### Text-only, fixed-PID delivery

After a real confirmation intent and all live gates, exact and application-bound destinations use the
same review-only transaction:

1. Require non-whitespace text that passes the safe-text classifier. LF is data; NUL, tab, carriage
   return, DEL, and C1 controls are rejected.
2. Reject drafts above **16,384 UTF-16 code units** before event construction. Non-BMP surrogate
   pairs count as two UTF-16 units and are preserved exactly; no chunking or normalization occurs.
3. Construct exactly one `.privateState` event source and one modifier-free Unicode key-down/key-up
   pair carrying the complete draft. Both events target the captured positive PID.
4. Read back the exact full payload, phase, empty flags, fixed FeishuSpeech tag, common source,
   `eventSourceUnixProcessID == getpid()`, and captured target PID for both events before the first
   post. Any construction, tag/readback, source, payload, or PID mismatch fails with zero posts.
5. After pair construction/readback, complete binding-specific identity, Accessibility trust, Secure
   Input, frontmost, and fixed-target validation in the final leading/trailing security sandwich.
   Per-AX cancellation/deadline checkpoints surround each synchronous message; cancellation wins over
   deadline. No validation runs while the final commit locks are held, and no application activation is
   part of the route. A transition observed before key-down fails pre-boundary with zero posts.
6. Once key-down is posted, the submission boundary is crossed and key-up is still attempted
   synchronously. A post-boundary fault, cancellation, epoch drift, or postflight uncertainty is
   `submittedUnverified`/uncertain, never cancellation or consumed success.

The OS does not provide an application-level receipt for `CGEventPostToPid`. A local submission
therefore never claims that the target displayed or consumed text. The route has no Return key event,
virtual-key V, Cmd+V, clipboard object, automatic retry, fallback copy, or retarget.

### Failure and draft retention

Pre-boundary failure returns the exact draft to `.editable` with fixed feedback and zero target events.
Post-boundary `submittedUnverified` is terminal: it makes no consumption claim, permits no resend, and
does not re-expose ordinary Send/Return. Duplicate clicks, stale callbacks, late focus completion,
monitoring loss, discard, cleanup, and lifecycle cancellation cannot create another attempt.

When the bounded post-release drain expires, `expirePostReleaseDrain` snapshots the latest preview
before interaction cleanup, fences late review-transition callbacks, and clears the current
`ReviewSurfaceAuthority`. If the same generation still owns a non-empty, safe, <=16,384 UTF-16
preview eligible for recovery, it renders the exact text in the same panel as the non-authoritative
read-only `ReviewReadOnlyPhase.recovery` surface; LF remains inert data and is retained exactly. The
surface shows fixed incomplete-recognition/read-only feedback, clears draft/confirm/discard callbacks,
materializes no Send button or qualified Return editor, and cannot reach delivery. Only authoritative
action 2 plus the recorder barrier may install `.editable`. No append, AX/Unicode/keyboard output,
pasteboard/copy, retry, or retarget occurs. Empty, unsafe, oversized, stale, or otherwise ineligible
previews retain the fixed failure/preservation branches.
