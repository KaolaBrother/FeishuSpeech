# D-34-01: Bound physical DNS and no URLSession hop

- Status: accepted
- Date: 2026-08-21
- Issues: #34
- Supersedes: D-32-01 URLSession connect-class hop for streaming token / `stream_recognize`,
  and D-32-01 Clash fake-ip / physical-interface DNS out-of-scope
- Retains: D-32-01 keep-alive primary, hostname/SNI `open.feishu.cn`, no `en0` string, no Feishu
  CDN IP list, no custom TLS verify block, no user-facing toggle, leftover framing, slice budget
  fields, coordinator outer backstops, and `file_recognize` on URLSession; D-28-01
  capture/recognition split and in-attempt cancel mapping

## Context

D-32-01 made keep-alive primary and prohibited `.other`, but keep-alive still resolved
`open.feishu.cn` with system DNS and hopped factory/packet/finish to URLSession on a
connect-class miss. Owner UAT of installed build 11 with Astrill OpenVPN `utun6` (`198.18.1.23`)
up showed system DNS (`1.1.1.2`) returning overseas `cdnbuild` A records (`98.96.x`). A bound
socket to those addresses was still slow; a keep-alive miss then hopped to URLSession, which
cannot bind and always used the TUN.

Issue #34 required physical-interface DNS for keep-alive, `IP_BOUND_IF` TCP to the resulting A
records, rejection of a connected socket whose local IPv4 is `198.18.*`, and **no** URLSession hop
for streaming token / `stream_recognize`. Hostname/SNI stays `open.feishu.cn`. There is no `en0`
string, no CDN IP allowlist, no custom verify block, and no user-facing toggle.
`file_recognize` stays on URLSession.

## Decision

Streaming factory, token refresh, and `stream_recognize` POSTs stay on an attempt-scoped
HTTP/1.1 keep-alive session. The send path is `BoundTLSSocket`, not `NWConnection` and not
system `getaddrinfo` for `open.feishu.cn`.

`DirectFeishuKeepAliveSession` snapshots a runtime wifi/wired `NWInterface` (no hardcoded BSD
name) and calls `BoundTLSSocket.connect(host: "open.feishu.cn", interfaceName:)`.

`BoundPhysicalDNS.resolveIPv4`:

- nameservers are DHCP option 6 on that runtime physical interface (SystemConfiguration service
  IDs, not a hardcoded `en0`), then recursor **hostnames** `dns.alidns.com` /
  `public1.114dns.com` (not IP literals);
- recursor hostnames are resolved with `getaddrinfo` and used only as UDP/53 destinations after
  tunnel-range filtering; they are never TLS peers or HTTP `Host` / SNI;
- each nameserver is queried with bound `SOCK_DGRAM` / `IPPROTO_UDP` / `IP_BOUND_IF` / port 53;
- A records skip `198.18.0.0/15` via bitmask `(ip & 0xFFFE_0000) == 0xC612_0000`;
- empty or all-tunnel answers fall through to the next nameserver; none left is
  `connectionFailed`.

TCP uses `IP_BOUND_IF` and tries remaining A records in order until one connects. CFStream TLS
on the connected fd sets `kCFStreamSSLPeerName` to `open.feishu.cn` and
`kCFStreamSSLValidatesCertificateChain = true`. There is no `sec_protocol_options_set_verify_block`.
A connected socket whose `getsockname` IPv4 has prefix `198.18.` is closed without HTTP.

Production keep-alive / bound-TLS / transport-context sources contain no dotted-quad literals.

`TransportAttemptContext.send`:

- keep-alive is **primary** for factory/packet/finish;
- a connect-class / no-HTTP miss **rethrows** and does **not** hop to URLSession;
- completed HTTP, including 4xx, does not hop;
- `CancellationError` does not hop;
- keep-alive success is sticky-direct for the rest of that attempt;
- a new context starts on keep-alive again;
- abort uses keep-alive when a session is present; URLSession only when keep-alive is absent;
- a first-send keep-alive miss on the production (non-injected) path drops that session;
  coordinator outer retry reconnects on a new context;
- a mid-attempt sticky-direct drop still invalidates.

Slice budget **fields** are unchanged: factory 8+7+1 < 18, packet 14+14+1 < 30, finish 15+15+1 <
45. Per-request keep-alive deadlines are the **direct** slices. Coordinator outer backstops remain
factory 18 s, packet 30 s, finish min(drain, 45 s). The URLSession half of those budgets is not a
same-operation fallback for streaming token / `stream_recognize`.

`file_recognize` / `recognizeSpeech` stay on `executeURLRequest`. Keep-alive leftover remains the
raw framed end of one HTTP message, including chunked trailers.

## Consequences

- Tenant-token and streaming Bearer POSTs resolve and connect on the bound physical path, so a
  VPN-poisoned system resolver and a URLSession hop cannot pull those POSTs onto TUN.
- Recursor hostnames are a nameserver fallback when DHCP option 6 yields no usable A set
  (including Local Network TCC blocking LAN DNS). Their `getaddrinfo` lookup may still use system
  DNS; returned tunnel-range addresses are dropped.
- UDP DNS is unauthenticated beyond a 16-bit transaction ID. TLS to `open.feishu.cn` remains the
  identity boundary.
- Corp VPNs with `includeAllNetworks` and no physical wifi/wired path can still fail closed
  (`connectionFailed`); there is no URLSession hop to recover them on streaming token /
  `stream_recognize`.
- Whole-file `file_recognize` and abort-without-keep-alive still use URLSession (system DNS / VPN
  as the OS provides).
- Live unsigned validator on this worktree with Astrill `utun6` up (2026-08-21): system path local
  `198.18.1.23` → overseas `98.96` HTTP ~863 ms `volc-dcdn`; bound path local `192.168.0.145`,
  mainland A records, HTTP 57 ms Tengine. That is not an installed `/Applications` Fn-hold proof.
- `xcodebuild test` hung on the adhoc test-host Keychain; do not treat the suite as green.
