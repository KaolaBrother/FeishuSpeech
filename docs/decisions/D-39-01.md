# D-39-01: Review editor Return confirmation policy

- Status: accepted and implemented; keyboard-policy validation complete; Issue #40 v5 retains and
  hardens this policy; replacement Release installation and owner UAT pending
- Date: 2026-08-23
- Issue: #39
- Supersedes: D-38-01's editable-review bare-Return editing rule only
- Retains: D-38-01's original-target capture as amended by D-40-01, the v5 text-only delivery
  boundary, capture/journal production, recognition/retry/replay consumption, and independent
  review-axis decisions. Issue #40 v5 removes review pasteboard/Cmd+V delivery; that output change
  does not change this keyboard policy.

## Context

The historical Issue #38 contract made the review editor multiline and assigned bare Return to text
editing. The shipped review surface now routes Return at the native AppKit editor boundary so
confirmation cannot be mistaken for ordinary text insertion, while preserving multiline editing
and the current review authority boundaries. The review surface is the only route for accepted
interactions; legacy settings cannot restore direct output.

## Decision

- In an editable review, unmodified Return and keypad Enter confirm the current exact draft once.
- Shift+Return and Shift+Enter insert one LF and never confirm.
- Command+Return remains an explicit confirmation shortcut.
- Return while the editor has marked IME text is passed to the input method; the review shortcut does
  not consume that composition event.
- The `发送` button confirms. `取消`, Escape, and closing the editable window discard without target
  or pasteboard mutation. A whitespace-only draft remains editable but cannot confirm.

This decision changes only editable review UI keyboard routing. Captured target authority and
selection semantics remain D-38-01 as amended by D-40-01; v5's text-only Unicode delivery, without
clipboard restoration or Cmd+V, is the current output transaction. Capture/journal production,
recognition/retry/replay consumption, and the independent review axis are unchanged. The recording
overlay remains status-only. D-27-01's direct/continuous writer is historical and is not an
alternate route for an accepted Issue #40 interaction. Drain-expiry recovery is a separate
non-authoritative read-only surface that retains exact LF data and cannot expose Send/Return or
delivery; only authoritative action 2 plus the recorder barrier may enter `.editable`. D-40-01 v5's
nonactivating panel arbiter rejects blank/IME/modified/repeat/wrong-window/non-descendant Return before
intent creation; its final delivery gate builds/readbacks one pair before the security sandwich and
uses per-AX cancellation/deadline checks. This does not alter the keyboard policy above.

## Consequences and verification boundary

only the unmarked Return path is now a confirmation authority. Command+Return remains available for
existing users and keypad Enter follows the same unmodified/Shift/Command policy as the main Return
key.
