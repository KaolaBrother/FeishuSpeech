# D-32-01: Keep-alive primary and skip VPN/TUN

- Status: accepted
- Date: 2026-08-21
- Issues: #33
- Supersedes: D-28-01 streaming transport order (URLSession-first; next factory starts on
  URLSession)
- Retains: D-28-01 capture/recognition split, in-attempt cancel mapping, leftover framing, and
  slice budgets

## Context

D-28-01 made keep-alive Network.framework a same-operation fallback after a URLSession
connect-class miss (`preferNoProxies`, SNI `open.feishu.cn`). Owner Q2-B with issues #28–#31
rejected binding `en0` or skipping TUN. On 2026-08-21 the owner reversed Q2-B: skip VPN/TUN;
do **not** bind `en0`. VPN-on streaming was unstable because the primary path still followed
the TUN.

## Decision

Streaming factory, token refresh, and `stream_recognize` POSTs start on an attempt-scoped
HTTP/1.1 keep-alive `NWConnection` to `open.feishu.cn:443`.

`DirectFeishuKeepAliveSession.makeParameters()` sets TLS SNI `open.feishu.cn`,
`preferNoProxies = true`, and `prohibitedInterfaceTypes = [.other]`. Peer authentication stays
on the default TLS options. There is no custom verify block, no `en0` / `requiredInterface`
bind, no CDN IP list, and no user-facing toggle.

`TransportAttemptContext.send`:

- keep-alive is **primary**;
- URLSession hops once on a connect-class / no-HTTP miss;
- completed HTTP, including 4xx, does not hop;
- `CancellationError` does not hop;
- keep-alive success is sticky-direct for the rest of that attempt;
- URLSession fallback success is sticky-URLSession;
- a new context starts on keep-alive again;
- abort uses URLSession unless the attempt is already sticky-direct;
- a first-send keep-alive miss does **not** invalidate URLSession;
- a mid-attempt sticky-direct drop still invalidates.

Slice budgets are unchanged: factory 8+7+1 < 18, packet 14+14+1 < 30, finish 15+15+1 < 45.
Primary uses **direct** slices; fallback uses **urlSession** slices. Coordinator outer
backstops remain factory 18 s, packet 30 s, finish min(drain, 45 s).

`file_recognize` / `recognizeSpeech` stay on `executeURLRequest`. Keep-alive leftover remains
the raw framed end of one HTTP message, including chunked trailers.

## Consequences

- Tenant-token and streaming Bearer POSTs leave a consumer VPN/TUN when a physical route
  exists. That is the accepted Q2-B reversal.
- Corp VPNs that mark `includeAllNetworks` with no physical path, and Clash fake-ip DNS, stay
  out of scope; a keep-alive miss may still fall back to the system URLSession/VPN path.
- Capture/recognition split, in-attempt cancel mapping, leftover framing, and slice-budget
  invariants remain the D-28-01 record.
