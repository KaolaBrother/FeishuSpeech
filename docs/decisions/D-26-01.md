# D-26-01: Journal-indexed held-response output

- Status: Historical issue #26 contract; concatenation, frontier suffix output, and blanket
  Backspace prohibition superseded by D-27-01; retry/replay admission and release sealing retained
- Date: 2026-08-04
- Supersedes: D-25-01 output identity, replay, release-time final authority, and final-only/manual
  fallback clauses
- Affected boundaries: coordinator response ownership, retry/replay, release admission, continuous
  output, completion classification, privacy diagnostics

## Context

Installed build 5 exhibited a one-word visible-output stall. Privacy-safe runtime evidence for the
latest interaction recorded 66 HTTP-200 transaction summaries over 13.55 seconds while capture
continued. This proves that audio and successful HTTP exchanges did not stop after the first word;
it narrows the defect to response interpretation, coordinator routing, or output classification.
The old continuous append policy posted the first scalar and accepted later values only when they
were strict cumulative UTF-16 extensions, so disjoint, equal, shorter, or revised values could stop
visible progress even while responses continued.

The response semantic itself is unknown. FeishuSpeech and KaolaTerminal decode one opaque scalar
(`recognition_text`, with `text` fallback) from each successful response. Neither proves whether
successive values are cumulative hypotheses, deltas, independent segments, revisions, or a mixture.
KaolaTerminal replaces an opaque preview value; it does not provide a speech-text assembly rule.

The requested product behavior therefore needs an explicit local policy. It must not be described
as a discovered Feishu guarantee.

## Decision

> Supersession note: [D-27-01](D-27-01.md) replaces this section's text assembly and mutation
> policy. A journal index still owns a response at most once, but an owned response is a complete
> opaque snapshot, not a delta to concatenate. Equal snapshots emit nothing. Verified AX replaces
> its owned range; the generic keyboard owner replaces only this hold's text with grapheme-counted
> Backspaces plus the replacement suffix. The release and replay-admission clauses below remain
> current. D-27-01 also limits LF/multiline output to verified AX range replacement and makes the
> existing HID event tap's lock-protected interference epoch authoritative for generic keyboard
> mutation.

Each Fn generation owns one coordinator-local response-output ledger next to its ordered packet
journal. While the generation remains held and admission is open, every eligible packet response
may claim its stable journal index once. Claiming concatenates that response's raw UTF-16 scalar to
the held frontier in response order. String equality, prefix similarity, or revision shape never
defines response identity.

The same growing frontier is offered to exactly one selected continuous owner:

- a verified `CursorTextSession` replaces its captured, app-owned AX range with the frontier;
- a captured `CurrentFocusAppendSession` remains bound to the original PID and exact AX element;
- an AX-unavailable `CurrentFocusAppendSession` remains bound to one frontmost PID.

The append sink retains its prefix check as a delivery/no-resend invariant. Because the coordinator
now supplies a locally monotonic frontier, the sink posts only the newly appended UTF-16 units. It
does not infer anything about the relationship between raw provider values.

### Eligibility and recognition availability

A packet response can own output only when all of these are true:

- its generation and journal index are current;
- response admission remains open and release has not started;
- the scalar is non-contentless and safe for automatic output;
- automatic insertion is enabled;
- one continuous owner has been selected.

Recognition availability is separate from output eligibility. A usable, active, unsealed held
response counts as recognized even when `autoInsert=false`, the scalar is unsafe, or no output owner
can be acquired. Those paths complete without inventing an empty-result or streaming-failure state,
while retaining zero insertion, zero rewrite, and zero clipboard mutation. Contentless, stale,
sealed, and terminal responses do not establish held recognition availability.

### Replay ownership

The journal's zero-based packet index is authoritative across fresh retry attempts:

- a replay response for an already-owned historical index never owns output again, even if its raw
  scalar differs;
- a previously failed and therefore unowned index may claim output once when replay first succeeds;
- an index first owned during replay becomes historical on every later replay;
- new live packets continue with new journal indices after catch-up.

Replay no longer chooses a latest opaque catch-up value as the output frontier. It preserves audio
order while ownership prevents historical text from being re-offered.

### Release and terminal authority

Fn release and the 60-second cap synchronously close response-ledger and retry admission before any
await, recorder shutdown, stream drain, or session creation. After this boundary:

- in-flight packet responses cannot claim or append;
- replay, late partials, and late nonterminal finals cannot claim or append;
- the action-2 response cannot create first output, append a suffix, replace held output, or become
  a recovery value;
- finalization may only close the already-selected owner against the already-owned held frontier.

All release-time one-shot insertion, release-time final-only output, full-value resend, Cmd+V, and
manual clipboard recovery are removed from the production coordinator. Uncertain delivery never
authorizes retry, resend, a different writer, or copy.

### Preserved safety boundaries

This decision does not weaken destination or delivery authority:

- verified AX output remains generation-, PID-, exact-element-, caret-, range-, and read-back-bound;
- captured append output retains exact `CFEqual` focused-element validation;
- unbound append output remains fixed-PID best effort and cannot observe same-PID caret movement;
- Secure Input, unsafe controls, activation/PID/element drift, and delivery uncertainty fail closed;
- owner suspension is permanent for the generation;
- no path uses selection, cursor navigation, global HID posting, or uncertain resend; D-27-01
  narrowly permits PID-targeted Backspace for the generic keyboard owner's recorded text only;
- `CGEventPostToPid` still provides no target-control acceptance acknowledgement.

Installed Release owner UAT remains mandatory for visible target acceptance. A locally submitted
pair is not proof that the control displayed text.

### Diagnostics and privacy

The coordinator records transcript-free response receipts containing only typed or numeric control
flow:

- generation, retry ordinal, journal index, source, and event kind;
- eligibility and ownership outcome;
- raw-scalar and assembled-frontier UTF-16 lengths;
- coarse raw-response shape (`first`, `exactDuplicate`, `prefixExtension`, `shorter`, or
  `divergent`) for diagnosis only;
- selected output outcome.

Diagnostics never contain or hash transcript text, audio, credentials, tokens, stream IDs, raw
response bodies/messages, PID, focused-element identities or values, application/window titles, or
clipboard payloads. Shape classification does not influence ownership.

## Consequences

The concatenation consequences below describe issue #26 history and are not current after
D-27-01. They are retained to explain the build-6 regression and the correction boundary.

- Equal, disjoint, cumulative, shorter, and revised raw scalars on distinct eligible packet indices
  all advance the local held frontier once.
- The policy may visibly duplicate cumulative or revisable provider values. That is an accepted
  product consequence of the user-selected local concatenation policy, not a provider-semantic
  assertion.
- Retry preserves exact-once output ownership without relying on text comparison.
- Release only seals output already offered while held; action 2 is no longer output authority.
- Recognized-but-ineligible text no longer becomes a false empty-result or transport error.
- PID, exact AX element, Secure Input, drift, uncertainty, and no-resend guarantees remain stronger
  than continuous-output preference.
- Lifecycle-free XCTest evidence is 272/272 passing. Independent correctness and security reviews
  pass. Installed Release UAT remains pending, so no end-to-end or broad-compatibility claim is made.

## Provider semantics and remaining unknowns

The following remain unverified and must not be claimed:

- whether Feishu intermediate values are cumulative, disjoint, per-packet, stable, or revisable;
- whether equal values on different packets represent repetition or unchanged recognition state;
- whether action-2 text is complete, a delta, a revision, or empty;
- whether a submitted PID-targeted Unicode pair is visibly accepted by a real control.

Future UAT may measure only transcript-free lengths, shapes, indices, ownership, routes, and typed
outcomes. It must not retain speech text or other forbidden payloads.

## D-25-01 supersession boundary

This decision supersedes D-25-01 statements that:

1. raw partial strings are replacement-state output identity;
2. an action-2 final is authoritative for output;
3. replay publishes a latest catch-up hypothesis;
4. release may append/finalize from final text or create one-shot/final-only output;
5. zero-attempt unsafe or failed-owner paths may copy text for manual recovery;
6. an established stream is never replayed or every recoverable stream failure immediately ends the
   Fn generation.

D-25-01 remains historical context and remains authoritative only where it does not conflict with
this decision: verified AX range ownership, generation safety, security fail-closed behavior,
privacy, no destructive editing, captured destination identity, and no whole-file fallback.
