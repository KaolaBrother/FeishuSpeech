# D-27-01: Opaque snapshot replacement with owned keyboard reconciliation

- Status: Owner-approved issue #27 contract; implementation and installed Release UAT pending
- Date: 2026-08-04
- Supersedes: D-26-01 concatenation/frontier-suffix policy and blanket Backspace prohibition;
  D-25-01 blanket synthetic-Backspace rejection
- Retains: packet-index replay ownership, fixed destination, Secure Input and interference
  suspension, generation/admission safety, action-2 cleanup authority, and privacy boundaries

## Context

Release 1.0 build 6 repeated recognized words while Fn remained held. Privacy-safe receipts showed
distinct live packet indices returning identical complete values while the coordinator appended
each value to a growing frontier. Packet identity correctly prevented replay of the same journal
index, but it was incorrectly used as a text-assembly rule.

Feishu streaming responses are complete opaque recognition snapshots. A later snapshot may be
equal, longer, shorter, or revised. Packet replay ownership answers whether a response for an audio
index was already processed; it does not say whether response text is new.

## Decision

Each held generation owns two independent states:

- admission plus `ownedPacketIndices` rejects stale generations, sealed callbacks, and replay of an
  already-owned journal index; and
- `latestSnapshot` stores the last eligible complete response and is never a concatenation.

For a newly owned packet index, an empty or unsafe value changes neither snapshot nor output. A
value exactly equal to `latestSnapshot` is a `duplicateSnapshot` and emits no output event. Any
different value replaces `latestSnapshot` and is offered whole to the selected output owner. A
replayed historical index remains suppressed even if a later attempt returns different text; the
first previously failed, newly owned index may advance the snapshot once after recovery.

### Output owners

A verified AX writer receives the raw latest snapshot and replaces its one verified app-owned
range. Equal snapshots remain no-ops; shorter and revised snapshots replace that same range.

An arbitrary current-focus target uses one serialized keyboard replacement transaction. Compare
the previous and next snapshots as Swift extended grapheme clusters (`Character`), with no Unicode
normalization:

```text
oldCharacters = Array(previousSnapshot)
newCharacters = Array(nextSnapshot)
commonCount   = exact longest-common-prefix count
deleteCount  = oldCharacters.count - commonCount
insertText   = String(newCharacters.dropFirst(commonCount))
```

The transaction posts exactly `deleteCount` PID-targeted Backspace down/up pairs, followed by one
modifier-free Unicode insertion down/up pair when `insertText` is non-empty. All required events
are constructed before any event is posted and use one private tagged event source. The Backspace
count never uses bytes or UTF-16 units and can never exceed the text recorded as owned by this hold.
`previousSnapshot` advances only after the complete transaction is submitted successfully.

| Previous | Next | Keyboard transaction |
|---|---|---|
| `same` | `same` | no events |
| `hello` | `hello world` | type ` world` |
| `hello cat` | `hello car` | Backspace x 1, type `r` |
| `abcd` | `ab` | Backspace x 2 |
| `one` | `two` | Backspace x 3, type `two` |
| `family-emoji + x` | `family-emoji + y` | Backspace x 1, type `y` |

This is a narrow supersession of D-25-01 and D-26-01. It does not authorize Shift+Arrow selection,
global HID posting, pasteboard output, rollback, deleting pre-existing user text, or resending after
uncertainty.

### Target and safety boundary

The output owner binds one frontmost PID and never retargets. A captured target additionally keeps
its exact AX element checks. Generation/admission, bound PID, available destination validation, and
Secure Event Input are checked immediately before and after a transaction. Physical keyboard or
mouse input that could edit or move the caret permanently suspends the hold; Fn transitions and
FeishuSpeech-tagged events are exempt. Construction failure, activation/destination drift, secure
input, or delivery uncertainty also suspends permanently without rollback.

The generic route remains best effort: application-initiated same-PID caret movement cannot be
proved without AX. FeishuSpeech does not ask the user to confirm cursor location and does not
request a new runtime permission during the hold.

### Release and recovery authority

Fn release closes snapshot and retry admission before recorder or transport finishing begins.
After sealing, partial, terminal, retry, and replay callbacks produce zero keyboard events. Action
2 remains transport cleanup/finalization authority only; it cannot append, replace, paste, copy, or
restore text. A recoverable failure while Fn remains held preserves `latestSnapshot`; historical
replay indices cannot retype it, and the first newly owned response reconciles against it.

Reset, sleep, permission loss, secure input, destination loss, and generation invalidation close
the keyboard owner before asynchronous cleanup.

## Diagnostics and privacy

Receipts may contain generation, attempt, packet index, source/event kind, replay/admission result,
the decision (`first`, `duplicateSnapshot`, `extension`, `shorter`, `revision`, or `suppressed`),
previous/new/common-prefix UTF-16 and `Character` counts, Backspace and insertion counts, route,
and transaction outcome. They never contain or hash snapshot text, PCM, credentials, tokens,
stream IDs, target text/title, or clipboard contents.

## Consequences and verification boundary

- Repeated identical snapshots on different live packet indices produce one visible mutation.
- Extensions type only the suffix; shorter and revised snapshots delete exactly the old divergent
  grapheme tail before typing the replacement suffix.
- AX and generic keyboard routes implement the same replace-owned-provisional-output semantic with
  different proof strengths.
- Fixed-target and fail-closed suspension reduce risk but do not prove target acceptance or
  same-PID caret stability.
- Installed Release UAT remains required across native, terminal-style, Electron, emoji/CJK,
  repeated-silence, revision, focus/input interference, recovery, and release-race cases.

No broad cross-application Backspace compatibility or end-to-end success is claimed until that UAT
is recorded.
